## 分类作为共同规则

`CombatDefinition` 保存攻击方式与物理类别，`UnitDefinition` 保存职责。远程步兵由“步兵 + 远程攻击”推导，无需维护另一份手写单位列表；军事人口资格由职责推导。伤害、AI、操作权限、治疗、图鉴、选中面板使用同一份数据。

| 单位 | 类别与攻击 | 职责 |
|---|---|---|
| 剑士、盾卫、长矛兵 | 步兵 / 近战 | 作战 |
| 弓箭手、弩手 | 步兵 / 远程 | 作战 |
| 骑士、轻骑兵、战象 | 骑兵 / 近战 | 作战 |
| 投石车、加农炮、重型火炮、三管短炮 | 攻城器 / 远程 | 作战 |
| 工程兵、牧师 | 步兵 / 近战 | 支援 |
| 农民 | 步兵 / 近战 | 建设 |

用户已确认三管短炮与防御塔的步兵附伤扩展到全部步兵，因此也包括弓箭手、弩手和农民。三管短炮对弓箭手单发25、对弩手28、对农民30；防御塔对弓箭手14、对农民19。骑兵、攻城器的分类不受此项变化影响。

类别与子类别附伤重叠时只取最高匹配值，避免无意重复相加。现有数据不存在需要叠加的规则。每次命中仅遍历攻击者的少量附伤配置，不构造标签数组或扫描全场单位。

工程兵、牧师仍占军事人口，农民仍使用农民名额；建设、采集、自卫、治疗目标与AI支援调度保留原行为。AI继续招募原有阵容，但能识别弩手的远程步兵威胁。肉鸽已有的远程步兵增益与布阵判断也改用共享分类。

## 图鉴与模型

左侧可按兵种类别、近战/远程攻击、作战/支援/建设职责组合筛选；右侧单位名称下显示对应标签。支持清除条件、空结果提示，生产或选中面板跳转到具体单位时会清除妨碍定位的筛选。

- “远程步兵”显示弓箭手、弩手。
- “支援”显示工程兵、牧师。
- “建设”显示农民。
- 建筑与科技页面保留原入口，单位筛选只作用于单位页面。

采用原生 `OptionButton` 与保存的场景节点；动画使用已有 `AnimationPlayer` 流程。取景和紧凑标签沿用项目现有界面风格。[Godot OptionButton](https://docs.godotengine.org/en/4.6/classes/class_optionbutton.html)、[AnimationPlayer](https://docs.godotengine.org/en/4.6/classes/class_animationplayer.html)。

弩手模型共 **12个刚性分件、4,076个三角面**。开放式软帽、衣袖和衣料承担阵营色；皮甲、木弩、金属弩臂保留材质本色。制作了横置短弩、双手握持、弓弦、前端脚踏环、弩矢袋和发射口。待机、行走、发射及装填均为保存的原生动画，0.20秒发射与逻辑前摇一致。

视觉检查实际查看了正背侧面、四分之三、俯视、面部与握持特写，24帧行走与24帧攻击采样，以及批量渲染下的同场比较、阵营色、战斗与死亡。根据首轮画面将弩前移并重新计算手臂姿态，修正武器嵌入胸口和手部遮挡；补齐颈部与衣领的衔接。

| 同版本对比 | 中位帧耗时 | P95 | 采样期间发射数 |

| 弓箭手 | 11.246毫秒 | 21.169毫秒 | 1,000 |
| 弩手 | 12.175毫秒 | 23.370毫秒 | 1,250 |

这是不同单位负载的抽查，**不是修改前后性能基线**，不能据此声明旧场景满足5%/10%的回归阈值。独立的300发弩矢测试在超过256个视觉对象容量时，仍完整造成1,500伤害，没有因视觉池不足漏算或重复结算。穿甲与类别伤害的100,000次纯计算耗时约138毫秒。
