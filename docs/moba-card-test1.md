# MOBA卡牌模式 test1

2026-09-18，单人原型。玩家在左、电脑在右，控制各自英雄，军队完全由兵线指挥器控制。

## 界面与参考

视觉主张：清爽白色与浅灰紫面板、深蓝灰文字，绿色表示可操作，兵种类别使用蓝／橙／紫色条，借鉴用户提供的JR东日本截图的信息层次，不复制其标识和素材。

内容布局：战场占据主画面；顶部显示双方大本营、对局时间、金币和下一波计时；底部左侧为英雄生命、技能与视角按钮，中间为五张军队牌，右侧为小地图。底部默认85%大小，可在小地图旁用“− / +”或暂停菜单滑块调整为70%～100%，并自动保存。卡牌使用游戏自身三维单位肖像，保持比例，不使用额外风格的生成人物图。

交互主张：面板保持稳定，卡牌悬停抬起、补牌时淡入；拖动时原卡半透明、战场显示绿色出牌提示；技能冷却显示秒数。参考`Documents/sys2_cardgame(仅参考用)`的悬停抬起、上拖出牌、取消回手和动画与结算分离的思路，独立实现本模式代码。

原生实现采用保存的Control场景、Resource牌定义、信号、Tween与Godot拖放回调：[Control拖放](https://docs.godotengine.org/en/4.6/classes/class_control.html)、[资源属性](https://docs.godotengine.org/en/4.6/tutorials/scripting/gdscript/gdscript_exports.html)。

## 规则与当前平衡

- 地图200×56，纵深为7个大本营的8单位深度。左右镜像：大本营x=±87、重型要塞±61、城堡±37、两个炮塔±15／z=±9，中间留空。森林、营地、路标、碎石与草地复用林海远征前哨站的三维素材，道路保留通行宽度。
- 双方每8秒从大本营派出2长矛兵、3弓箭手、1剑士，第一波在8秒。卡牌即时从本方大本营周边的有效空位出兵；不会直接投送到鼠标位置。
- 初始240金币。敌方普通单位死亡，所有敌对玩家各获得其当前基础造价的20%，四舍五入、最低5金币；不要求尾刀。英雄和建筑不提供此项金币，不提供被动收入。
- 五张手牌，打出后1.5秒补牌。初版固定牌组循环洗牌，独立随机源、独立牌实例编号；将来可替换为赛前选择的牌组资源。牌类型使用枚举，首版只启用军队牌。
- 每局选择新洗牌种子；场景的`shuffle_seed`设为非零值可复现牌序。两方初始手牌相同，后续分别抽牌。
- 兵线指挥器按兵种与人数分配上下两路；后续部队展开接敌，近战分散接敌目标，远程进入独立射击位置，攻城炮优先拆塔。指挥器只下达原生移动、攻击和坚守命令，不修改小兵寻路、碰撞或攻击判定，也不打断正在出手的攻击。电脑使用同一金币、手牌、补牌和出兵规则，会攒钱购买当前需要的攻城牌。
- 工程保护上限为每方240名普通单位；满员时免费波次等待，不能花金币购买超出容量的军队。出口被堵时不扣卡、不扣金币。
- test1采用摧毁对方大本营获胜；英雄阵亡15秒后在己方大本营复活。阵亡期间兵线和出牌继续。暂停冻结对局、出兵、抽牌、技能及复活时钟。
- 英雄沿用已有形象和200生命、20+20伤害、3/3护甲、4.2移速、20射程、0.65秒射击间隔。俯视视角WASD按屏幕方向移动，斜向速度归一；移动时会向射程内可见敌人射击，左键可按鼠标方向持续瞄准射击。右键移动或指定攻击，H原地待命，E／R技能，Y切换镜头跟随，空格定位英雄；中键拖动或点击小地图进入自由观察。F5切换第一人称，**本模式无限子弹且无需换弹**，共享同一实体与武器冷却。第一人称数字1～5出牌，Tab暂时释放鼠标便于操作卡牌，仍可用E／R。
- E肉体强化：按下即开始20秒独立冷却；此后每满1秒恢复25生命，共5次，不溢出最大生命。
- R士气昂扬：按下即开始25秒独立冷却；施放瞬间为自身和水平半径3内存活友军提供25%移速加成，持续3秒。同类效果刷新持续时间，不叠加倍数。
- 当前开放全地图视野，便于观察兵线与平衡；不接入联机、牌组编辑、装备背包或额外资源系统。

## 实施记录

当前版本：test1，可玩，等待体验反馈。

已完成：主菜单入口、原生森林战场、十种军队牌、五张手牌与随机补牌、每8秒自动出兵、击杀收益、兵线AI、双方英雄、E/R技能、双视角无限弹药、15秒复活、胜负结算、暂停/设置/重开/退出。固定建筑数值存于本模式资源，普通单位仍读取既有定义。

界面采用保存的原生场景。卡牌预览使用独立拖拽容器保持鼠标偏移，投放面始终存在且透传普通世界输入，解决快速拖动后立即松手的投放丢失；校验卡牌实例编号，防止补牌后执行旧拖拽。扣费在完整出生位置预留成功之后进行。第一人称使用已有蓝天，缩小透视血条，声音的距离裁剪跟随当前英雄监听器。

兵线AI每0.5秒更新一次双方战况快照，将待处理部队按前后排、双方交错排列，每个物理帧最多处理40名单位；每2.8秒考虑出牌。本地接敌、攻击前摇、寻路与碰撞由既有单位系统负责。电脑使用同一牌价与收益规则，英雄生命不足时撤退并持续恢复到重返前线的阈值。正在出手或顺利接敌的部队保留当前命令。

仅本地单人，不部署线上中继。`data/moba`与沙盒数据一样，不纳入现行遭遇战联机规则指纹；未来开放此模式联机时需要单独扩展协议。

### 验证与限制

- 模式规则68项、真实GUI输入28项、原英雄沙盒79项、原英雄战斗18项、拥堵等待22项、真实群体接敌152项，共367项通过。覆盖无限弹药与原有10发换弹同时成立、技能周期/半径/叠加、错误扣费、玩家不能指挥小兵、F5与E/R实际按键、拖拽取消/释放、暂停/设置、重复进入退出。
- 将暂存内容导出为独立项目后，重新导入并通过68项规则和28项界面检查，确认交付不依赖工作区中未提交的地图、菜单主题或项目设置。
- 持续原生对局：一场玩家不干预的测试在339.63秒正常结束，电脑出牌16次，依次突破外塔、城堡、要塞与大本营；峰值107个普通单位，未发现人数计账偏移、负金币、无穷坐标或人口越界。此结果用于证明流程闭合，不代表平衡已经定稿。
- 实际渲染检查：1600×900的主菜单、基地、前线、卡牌拖拽与第一人称；1280×720画面检查，并以GUI断言检查1920×1080与2560×1080布局。肖像保持比例。
- 高负载：RTX3080、1600×900、Forward+、关闭垂直同步，以固定60渲染步进、30Hz战斗模拟采样1200帧；峰值444个单位（含英雄），原生伤害与寻路保持开启。实测帧耗时中位22.995毫秒、P95为34.436毫秒；物理处理采样中位24.405毫秒、P95为29.568毫秒。该极端拥挤场景存在明显压力，不能据此声称400余单位下稳定60帧。常规前线画面本机观测约260～270渲染帧/秒，该短段观测不等同于全局性能保证。
- 本轮修复了新场景的天空雾色遮蔽、近距离血条过大、拖拽预览偏移、快速松手丢失投放、空间音效仍按RTS监听器裁剪等问题。
- 待反馈：单位牌价、20%击杀收益、固定建筑强度、双方推进节奏，以及此套浅色界面的实际体验。

验证截图只保留在忽略目录`.local/moba-test1`，不提交到仓库。原工作区的地图、菜单主题、音量、导出等改动保留；主菜单文件仅提交本任务新增入口。

## 2026-09-19：统一控制台与卡牌动效

依据本轮生图设计稿重做底部界面：连续的浅灰白色控制台承载小地图、五张军队牌和英雄操作，区域以细分隔线划分。沿用JR参考中的蓝灰文字、绿色操作反馈和类别色，减少独立浮动面板。卡面使用编号色签、淡色画面区、大幅兵种形象、数量及费用胶囊；十种军队牌的专用取景保存在继承场景中，不改变图鉴取景。

图标使用本轮生图工具生成的透明PNG图集，按透明通道边界定义原生AtlasTexture区域。保留原始像素，所有图标和单位肖像使用保持比例的显示方式；不把整张效果图贴在界面上。卡牌、技能按钮和控制台均为可编辑的原生场景。

| 操作 | 表现与时长 |
|---|---|
| 界面进入 | 控制台上移并淡入，0.40秒 |
| 悬停卡牌 | 上抬17像素、放大至1.035倍，0.18秒；仅当前肖像以15Hz播放待机 |
| 拖动 | 原卡保持半透明，跟随鼠标的独立预览略微倾斜，投放提示淡入 |
| 取消拖动 | 卡牌从松手位置归位，0.24秒，不扣除金币 |
| 出牌成功 | 卡牌上移、缩小并淡出，0.25秒；部队和扣费立即结算 |
| 等待补牌 | 固定牌位显示剩余秒数与实际补牌进度 |
| 补牌进入 | 新卡上移、淡入并轻微回弹，0.34秒 |
| 拒绝出牌 | 卡片短促横向反馈，0.24秒，配合失败原因提示 |
| 技能与金币 | 名称保持可见，技能点击及冷却完成有短暂反馈；冷却条单独显示，金币数字平滑变化 |

悬停变换与出牌／补牌动画分属不同节点，避免快速移入移出互相打断。牌实例编号和玩法时钟仍归对局管理，动画不延迟扣费、不控制补牌、不改变冷却。暂停窗口始终覆盖抬起的卡片；控制台空白处会拦截战场右键命令。进度条取消通用内边距，避免刚开始冷却时出现虚假的最小填充。

实现主要使用保存的[AnimationPlayer动画](https://docs.godotengine.org/en/4.6/classes/class_animationplayer.html)、[原生拖放及完成通知](https://docs.godotengine.org/en/4.6/classes/class_control.html#class-control-method-is-drag-successful)和动态目标Tween。

编辑入口：

- `scenes/moba/hud.tscn`：整块控制台、顶部信息、投放提示与模态窗口。
- `scenes/moba/card.tscn`：卡面、空牌位、进入／出牌／拒绝动画；`card_drag_preview.tscn`保存拖拽容器。
- `scenes/moba/card_portraits.tscn`：本模式专用的十种兵种取景。

- `tools/build_moba_ui.py`：仅生成上述UI资源，不重写地图、牌价或兵种数值。完整模式构造工具调用它，避免旧版布局覆盖本轮修改。

本轮截图与录像存放于忽略目录`.local/moba-ui`；最终仅保留设计稿、必要实拍与压缩后的短视频，删除原始AVI及临时过渡帧。

## 2026-09-19：林地地表精修

原地面将同一张泛用纹理同时染成草地与道路，过渡过宽，建筑周围也是圆形土色块。此次为本模式加入独立的草甸、夯土、林下落叶、石铺四种手绘纹理，并细化不规则路肩、浅车辙和草土交接。纹理由生图工具生成后等比例切分；未修改肉鸽模式共用材质。

十座固定建筑周围增加贴合轮廓的石铺庭院与倒角石边；旧路面分段留下有缺口、色差和磨损的三维铺路石。低矮草簇集中在路肩，蕨类与落叶集中于林边。经过两轮实拍修正，压低了过密草丛，减少铺路石的整齐重复感。

这些都是保存的静态网格与原生 MultiMesh，没有新增地表脚本、粒子、碰撞体或每帧散布。新增1,999个细节实例按25米分区，使用40个批量节点进行视锥裁剪；地面仍为22,400个三角面，庭院80面，单块倒角石24面。地面高度、建筑位置、出生点、地图边界、既有碰撞与导航资源保持不变，石块最多仅在视觉上高出行走平面3.5厘米。

编辑入口：

- `assets/textures/moba_ground/`：四种纹理、mipmap及压缩导入设置。
- `assets/models/environment/moba/ground_material.tres`、`ground.gdshader`：世界坐标采样、草土与林下过渡、浅车辙。
- `scenes/moba/ground_details.tscn`：可编辑的庭院与分区细节；由`test1_map.tscn`原生实例化。
- `tools/build_moba_ground.py`：仅重新生成地表，不重写卡牌、界面、建筑数值或导航。先运行它，再运行`Godot --headless --path . --script res://tools/bake_moba_ground.gd`导出三个网格。完整地图工具也调用同一入口。

实现依据Godot的[空间材质着色器](https://docs.godotengine.org/en/4.6/tutorials/shaders/shader_reference/spatial_shader.html)和[原生MultiMesh](https://docs.godotengine.org/en/4.6/tutorials/3d/using_multi_mesh_instance.html)。所有采样是静态的；纹理使用mipmap与各向异性过滤，减轻缩放和第一人称斜视时的闪烁。

验证：模式规则68项通过；检查基地、前线交战、第一人称近看、1600×900及1280×720画面，渲染日志无错误；离线构造可重复生成一致结果。逐项比对确认地图既有结构和导航未变，原工作区54个改动文件的内容亦完整保留。

性能为RTX3080、Forward+、1600×900、关闭帧率限制下的固定镜头静态对比，每个角度预热120帧、采样600帧。基地／前线／第一人称的整帧中位数分别由2.784／2.785／2.778毫秒变为2.863／2.782／2.778毫秒；GPU中位数由1.624／1.573／1.513毫秒变为1.947／1.647／1.643毫秒。新增材质和细节有渲染成本；该检查针对地表，不代表大规模兵战性能。最终实拍与测量保存在忽略目录`.local/moba-ground`。

### 同日调整：更简洁、可爱的方块质感

用户确认上一版方向可用，但要求减少细节与色彩丰富度，带一些Minecraft式方块感。本版重新用生图工具绘制四种地表：草绿、奶油米色、暖灰为主，使用少量低对比度的大几何色块。草地材质取消多尺度旋转混合、细碎路肩噪声及车辙，林下也统一为略深的绿色；颜色可通过`ground_material.tres`的`grass_color`、`earth_color`和`texture_strength`调整。

庭院石块与路边铺石变大，减少不规则缺口、色差和磨损。上一轮新增地表细节由1,999处减至585处（减少70.7%），分区批量节点由40个减为16个；保留零星矮草，移除额外散布的碎石、蕨叶和落叶。铺路石改回原生StandardMaterial3D，删除不再使用的磨损着色器。地面每像素的纹理采样由六次减至四次。

四张源纹理仍为627×627，采用不透明原图的等分裁切；合计PNG体积由约3.05MiB降至0.76MiB。新资源替换原素材，未堆积旧版贴图。

验证：68项模式检查通过；实际渲染检查基地、35秒前线交战、第一人称地表近景及1280×720画面，日志无错误。地图布局、碰撞、导航与玩法数值未改。新版实拍保存在忽略目录`.local/moba-ground-soft`。

### 同日调整：打散草地重复并明确方块边界

原来的镜像采样每16米出现一次同样的方块组合。现在草地与林下按固定世界坐标种子，分配随机偏移、四分之一圈旋转与0.85～1.18倍缩放；3.5米采样区域采用共享顶点的三角网格混合，消除区域接缝。图案固定在地面上，保持现有配色、块面尺寸范围与装饰密度。

针对方块边缘偏软，草地与林下改用最近邻的各向异性 mipmap 过滤，并将采样层级轻微偏移半级。远处仍使用 mipmap；没有全局关闭抗锯齿或给整幅画面加锐化。显式梯度来自连续世界坐标，避免随机偏移造成错误的模糊层级。实现使用Godot的[原生过滤模式](https://docs.godotengine.org/en/4.6/classes/class_basematerial3d.html#enum-basematerial3d-texturefilter)及[textureGrad](https://docs.godotengine.org/en/4.6/tutorials/shaders/shader_reference/shader_functions.html)。

没有新增素材、地表节点、网格或CPU逐帧工作；地面每像素纹理采样由4次增至8次。RTX3080、1600×900、Forward+同镜头静态采样600帧：基地／前线／第一人称的GPU中位数由1.888／1.834／1.560毫秒变为1.915／1.866／1.597毫秒，绘制调用与三角面数量一致。此结果仅代表本机地表渲染成本，不作为兵战整体性能保证。

检查基地、35秒前线交战、第一人称近景、近距离方块边缘及1280×720画面，最终渲染日志无错误。隔离时序抗锯齿与屏幕空间间接光后，镜头移开、缩放再返回，草地图像逐像素一致；原16米周期的水平边缘相关系数从0.970降至约0.00008。正常画面的原有抗锯齿及光照保持开启。本轮实拍与测量位于忽略目录`.local/moba-ground-variation`。
