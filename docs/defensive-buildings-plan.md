# 防御建筑扩展与逐项验收

顺序：**炮塔 → 城堡 → 重型要塞**。用户已确认分为三批，每个建筑单独验收；通过前不制作下一个建筑的模型、动画或玩法。数值由开发阶段负责设计，本轮不制作未来的 MOBA 卡牌模式。

炮塔定位为中段据点：单体输出20/秒，高于箭塔对普通步兵的约12.7/秒；造价超过两座首价箭塔，不能取代便宜的分散布防。对盾卫41伤害（4发）、剑士46（3发）、骑士41（3发）、战象45（8发）、普通加农炮46（4发）。无最小射程、无穿甲、无驻军、无生产，不受军队攻防或加长炮管科技加成。射程沿用建筑墙边到单位边缘距离，普通加农炮的13射程可在炮塔12射程之外攻击。

城堡以多目标持续火力保护大本营同等面积的防线；重型要塞以更高成本和更大占地换取清理密集部队的能力。重型要塞已获准进入第三批制作，验收前不开展 MOBA 模式。

## 第一批：炮塔

- 炮塔：低矮厚石台、砌块和拱门、露天回转炮架、厚壁炮口、队色炮箍与三面盾徽。尺寸与总部和箭塔同场检查。
- 离线仅导出炮塔；运行时实例化保存的原生场景，炮座独立转动，炮管由 AnimationPlayer 播放后坐与复位，Marker3D 提供真实发射点。
- 武器类型成为建筑定义的显式字段。旧建筑保留箭矢、节奏和发射规则；炮塔使用现有单体炮弹、声音和受控效果池。
- 农民施工、占地、取消退款、拆除、头像、图鉴与沙盒完整接入。电脑继续既有建造选择，能够识别、攻击新建筑。
- 主机决定瞄准与开火；客户端仅展示炮座角度和后坐，不重复伤害。新增快照契约更新协议版本，本轮不部署线上中继。
- 对外名称统一“箭塔 / Arrow Tower”；保留 `defense_tower` 内部 ID，以保持已保存地图和场景引用稳定。

### 城堡阶段

按用户确认进入第二批，仅制作城堡。四角堡楼、低墙门楼与中央主堡组成9×8占地的轮廓；前方两门小炮与主堡顶上一门炮各自转向和后坐。通过原生子场景复用已验收炮管，独立状态保存每门炮的目标、冷却和发射时刻。每座建筑共用一次错峰空间查询，优先分散，目标不足时允许集火。

农民建造超过六个操作时使用现有分页；图鉴明确展示每炮伤害、间隔和炮数。初始模型上限36,000三角面，检查炮管整圈转向、后坐与堡楼之间的间隙。
