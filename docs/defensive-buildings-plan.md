# 防御建筑扩展与逐项验收

顺序：**炮塔 → 城堡 → 重型要塞**。用户已确认分为三批，每个建筑单独验收；通过前不制作下一个建筑的模型、动画或玩法。数值由开发阶段负责设计，本轮不制作未来的 MOBA 卡牌模式。

|---|---|---:|---:|---|---|---|---|---|---:|
| 箭塔 | Arrow Tower | 保留现有递增价格，首座150 | 1000 | 10／10 | 4×4 | 20秒 | 16远程；步兵+3、骑兵+9 | 1.5秒 | 13 |

炮塔定位为中段据点：单体输出20/秒，高于箭塔对普通步兵的约12.7/秒；造价超过两座首价箭塔，不能取代便宜的分散布防。对盾卫41伤害（4发）、剑士46（3发）、骑士41（3发）、战象45（8发）、普通加农炮46（4发）。无最小射程、无穿甲、无驻军、无生产，不受军队攻防或加长炮管科技加成。射程沿用建筑墙边到单位边缘距离，普通加农炮的13射程可在炮塔12射程之外攻击。

城堡以多目标持续火力保护大本营同等面积的防线；重型要塞以更高成本和更大占地换取清理密集部队的能力。重型要塞目前只保存在本计划中，不提前添加可建造入口或未完成资源。

## 第一批：炮塔

- 炮塔：低矮厚石台、砌块和拱门、露天回转炮架、厚壁炮口、队色炮箍与三面盾徽。尺寸与总部和箭塔同场检查。
- 离线仅导出炮塔；运行时实例化保存的原生场景，炮座独立转动，炮管由 AnimationPlayer 播放后坐与复位，Marker3D 提供真实发射点。
- 武器类型成为建筑定义的显式字段。旧建筑保留箭矢、节奏和发射规则；炮塔使用现有单体炮弹、声音和受控效果池。
- 农民施工、占地、取消退款、拆除、头像、图鉴与沙盒完整接入。电脑继续既有建造选择，能够识别、攻击新建筑。
- 主机决定瞄准与开火；客户端仅展示炮座角度和后坐，不重复伤害。新增快照契约更新协议版本，本轮不部署线上中继。
- 对外名称统一“箭塔 / Arrow Tower”；保留 `defense_tower` 内部 ID，以保持已保存地图和场景引用稳定。

## 验证与交付

真实渲染检查正侧背、队色、炮口与转向、后坐和施工；功能检查单体伤害、范围边界、友军、失效目标、停战、暂停、建造与退款、地图占用、网络合法/非法快照与旧箭塔回归。截图保存在忽略目录 `.local/defenses/cannon_tower/`，只保留必要验收图。

采用 Godot 原生 [AnimationPlayer](https://docs.godotengine.org/en/4.6/classes/class_animationplayer.html)、[Node3D](https://docs.godotengine.org/en/4.6/classes/class_node3d.html) 与 [Marker3D](https://docs.godotengine.org/en/4.6/classes/class_marker3d.html) 保存部件、动作和炮口；无运行时几何生成。

### 城堡阶段

按用户确认进入第二批，仅制作城堡。四角堡楼、低墙门楼与中央主堡组成9×8占地的轮廓；前方两门小炮与主堡顶上一门炮各自转向和后坐。通过原生子场景复用已验收炮管，独立状态保存每门炮的目标、冷却和发射时刻。每座建筑共用一次错峰空间查询，优先分散，目标不足时允许集火。

农民建造超过六个操作时使用现有分页；图鉴明确展示每炮伤害、间隔和炮数。初始模型上限36,000三角面，检查炮管整圈转向、后坐与堡楼之间的间隙。

### 城堡 v1 验证记录（2026-09-17）

最终模型34,016个三角面、20个网格部件，主体石材、木构、金属与队色分别合并。蓝色屋顶、旗帜、主堡皇冠盾徽与炮箍提供阵营辨识。检查了正侧背、俯视、红蓝队色、三炮不同朝向和不同后坐阶段，以及图鉴、沙盒和与旧建筑同场的尺寸。整圈每15度、三个后坐阶段的实际炮管网格间隙检查通过。

火炮使用已保存的 [Godot 子场景](https://docs.godotengine.org/en/4.6/tutorials/scripting/nodes_and_scene_instances.html)，每门炮独立拥有 AnimationPlayer、转向部件与 Marker3D。原炮塔改为引用同一个炮组件，网格、位置、节奏保持已验收版本；原有视觉检查再次通过。建筑武器状态按索引保存目标、冷却、发射时刻，换目标不刷新装填；每次开火从对应炮口进入现有单体伤害流程。

性能样本：真实500单位物理空间，预热后120组、每组8次查询；炮塔平均246微秒，城堡平均286微秒、P95为291微秒。城堡每约0.35秒共用一次查询，没有为三门炮分别扫描全场。这是CPU目标搜索测量，不代表完整GPU帧耗时。300发炮弹同时存在时最多256个显示对象，44发省略显示仍全部结算伤害；下一轮复用已回收记录。

修正事项：建筑射程边界采用原生近似比较处理世界坐标浮点误差；同步开火回调中本体被摧毁或比赛结束时停止后续炮口释放；建造分页保留实时价格提示；建筑面板从定义读取护甲并显示多炮数量。迁移旧测试的单炮内部访问，同时更新已经过时的六人混战地图尺寸、投石车伤害和场景切换等待假设，运行时旧地图与旧单位数值未改动。

当前协议为**18**，建筑快照携带与定义炮数一致的有界数组，每项只有转向、俯仰和发射时间。主机选择目标并结算伤害，客户端按现有插值时钟独立展示三炮动作。线上 relay 未在本阶段部署。

验收入口：战争图鉴 → 建筑 → 城堡（开炮）；沙盒 → 防御建筑 → 城堡；正常对局选择农民 → 更多建筑 → 城堡。
